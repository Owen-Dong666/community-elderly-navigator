# Mind+ K10 实体端与电脑端智能体集成设计

## 1. 目标与成功标准

本阶段把已有的“电脑端智能体 + 浏览器 K10 模拟器”扩展为可由 Mind+ V2 图形化积木驱动的 K10 实体端。项目面向小学组展示，以稳定、易讲解、可复现为优先级，不追求不受限制的开放式对话。

用户已确认的基线方案是：

- Mind+ V2、K10 上传模式。
- K10 通过 Type-C 与电脑连接，使用串口 0 双向通信。
- K10 使用离线预设命令词做语音输入，使用板载中文语音合成播报。
- DFR1231 扩展板连接六路地图 LED。
- 电脑端继续负责知识库检索、步骤规划、安全校验和会话状态。
- 前期可连云端 OpenAI 兼容 API，后期仅改配置即切换到 Ollama `qwen3:0.6b`。

完成后应满足：

1. 学生能在 Mind+ 中打开、讲解和修改 K10 主程序积木。
2. 老人说出预设服务命令后，K10 把查询发给电脑端智能体。
3. K10 屏幕显示当前服务和步骤，扬声器播报，纸板地图只点亮对应地点 LED。
4. A 键重复当前步骤，B 键前往下一步，末步再按 B 结束并熄灯。
5. 查不到“办护照”等信息时，必须固定提示“当前资料中没有这项信息，请向社区工作人员确认”，且六个 LED 全部熄灭。
6. 浏览器模拟器中现有的文字扬声器符号改为清晰的小喇叭 SVG 图标。

## 2. 范围

### 2.1 本阶段交付

- Mind+ V2 K10 上传模式的积木程序流程和逐块搭建说明。
- 电脑端 USB 串口桥，在 K10 短指令与现有 REST API 之间转换。
- 六路 LED 的逻辑编号、推荐引脚映射和安全接线说明。
- 八个离线语音命令，覆盖常见服务和一个未知信息演示。
- 电脑端串口桥自动化测试、伪串口集成测试和实物验收清单。
- 浏览器模拟器扬声器 SVG 图标。

### 2.2 本阶段不做

- 不在 K10 上运行 Qwen3 0.6B；模型始终运行在电脑或云端。
- 不把所有自由语音转成文本。K10 离线识别首版只支持八个精心设计的命令词。
- 不让 Mind+ 直接调用大模型 API，也不在积木中保存 API Key。
- 不修改现有知识库的事实内容，本阶段仍使用并明确标注“幸福里社区”演示数据。

## 3. 总体架构

```text
老人语音 / A、B 键
          ↓
Mind+ K10 积木程序
  离线命令词识别
  屏幕 / 语音合成 / LED
          ↕ USB 串口 0（115200）
电脑端串口桥
  短指令解析
  当前 session_id
  REST API 转换
          ↕ HTTP 127.0.0.1
现有 FastAPI 智能体
  知识库检索 → 模型规划 → 安全校验 → 会话状态
          ↓
 Mock / 云端 OpenAI 兼容 API / Ollama qwen3:0.6b
```

分层的关键是：K10 只处理交互和设备控制；串口桥只处理通信转换；智能体核心继续处理检索、规划和安全边界。更换模型时不修改 Mind+ 积木。

## 4. 硬件和接线

### 4.1 设备

- 行空板 K10（板载麦克风、扬声器、屏幕和 A/B 键）。
- DFR1231 K10 IO 扩展板。
- 六个 LED、每路一个 220—330 Ω 限流电阻。
- Type-C 数据线，直接连接电脑 USB 口。

### 4.2 LED 逻辑映射

| LED | 地图地点 | 推荐数字引脚 |
|---|---|---|
| 1 | 小区入口 | P0 |
| 2 | 社区中心 | P1 |
| 3 | 卫生站 | P2 |
| 4 | 活动室 | P8 |
| 5 | 服务大厅 | P9 |
| 6 | 便民驿站 | P12 |

六路引脚在 Mind+ 启动时统一设为输出并写低电平。每个 LED 的正极通过限流电阻接信号引脚，负极接公共 GND。程序先执行“全部 LED 关闭”，再点亮目标 LED，因此正常状态下最多只亮一个。实物接线时以 DFR1231 板上丝印为准，不依靠导线颜色猜测引脚。

## 5. K10 离线语音命令

使用中文模式，唤醒词使用 K10 默认的“你好小行”。命令词在 Mind+ 中按官方要求用空格分隔的拼音填写，识别后映射为稳定的中文查询：

| 命令 ID | Mind+ 命令词 | 发给电脑的查询 |
|---:|---|---|
| 10 | `shu fa ban` | 我想报名参加书法班 |
| 11 | `tai ji quan` | 我想参加太极晨练 |
| 12 | `liang xue ya` | 哪里可以免费量血压 |
| 13 | `she bao` | 我想咨询社保 |
| 14 | `gao ling jin tie` | 我想咨询高龄津贴 |
| 15 | `lao ren zhu can` | 老人助餐点在哪里 |
| 16 | `shui dian bao xiu` | 家里水电坏了怎么报修 |
| 17 | `ban hu zhao` | 我想办理护照 |

首版的“语音查询”是有边界的离线命令识别，不宣称为任意口语听写。文字模拟器仍保留自由输入，用于测试知识库其他服务。

## 6. USB 串口短协议

### 6.1 基本规则

- 使用 K10 串口 0，波特率 115200，UTF-8 文本，每条指令以换行结束。
- 单行最大 1024 字节；超限、非 UTF-8 或未知指令被桥接程序拒绝。
- 纵线 `|`、回车和换行不允许出现在字段内；桥接程序在下发前把它们替换为空格。
- 该短协议只用于 Mind+ 积木容易处理的物理串口。现有内部 JSON Lines 模型保留，两者通过适配层共用 `SessionState`。

### 6.2 K10 发给电脑

```text
HELLO|1
QUERY|我想报名参加书法班
BUTTON_A
BUTTON_B
```

`HELLO|1` 表示设备协议版本。`QUERY` 创建新会话并替换桥接程序中保存的当前 `session_id`。按键指令只作用于当前会话。

### 6.3 电脑发给 K10

连接就绪：

```text
READY|智能体已连接
PING
```

桥接程序每 2 秒发送一次 `PING`。K10 用它更新“最后心跳时间”；连续 5 秒未收到心跳时，将电脑端标记为未连接、熄灭全部 LED，并显示“电脑连接已中断”。

一次完整状态使用边界指令包裹：

```text
STATE_BEGIN
MODE|display
SERVICE|书法班报名
STEP|1|3
TITLE|准备报名资料
BODY|带上本人社区居民卡和常用联系电话。
HELPER|步骤 1 / 3
SPEAK|请带上社区居民卡和常用联系电话。
LED|4
STATE_END
```

`LED|0` 表示全部熄灭。K10 只在收到 `STATE_END` 后一次性更新屏幕、LED 和播报，避免显示半帧数据。

桥接程序无法连接服务器时下发：

```text
ERROR|电脑端服务未启动，请联系工作人员。
```

K10 收到 `ERROR` 时熄灭全部 LED，显示并播报错误文字。

## 7. Mind+ 积木程序设计

### 7.1 变量

Mind+ 中创建以下变量：

- 通信：`rxLine`、`computerReady`、`frameOpen`、`lastPingTime`。
- 按键：`buttonAFlag`、`buttonBFlag`。
- 显示缓存：`mode`、`serviceName`、`stepNow`、`stepTotal`、`titleText`、`bodyText`、`helperText`。
- 执行缓存：`speechText`、`ledIndex`。

### 7.2 自制积木

把程序拆成六个能单独理解的自制积木：

1. `全部LED关闭`：把 P0、P1、P2、P8、P9、P12 全部写低电平。
2. `点亮地图地点(编号)`：先全关，再按 1—6 对应写高电平；0 和非法编号保持全关。
3. `显示初始页`：显示“街坊办事小助手 / 请先说你好小行 / 再说想办的事情”。
4. `发送查询(文字)`：显示“正在查询”，熄灯，串口输出 `QUERY|` 与查询文字。
5. `处理电脑指令(一行)`：识别 `READY`、`PING`、`STATE_BEGIN`、各字段、`STATE_END` 和 `ERROR`，只写缓存变量。
6. `应用完整状态`：按缓存统一刷新屏幕，点亮地点，再以语速 1 合成并播报 `speechText`。

### 7.3 K10 主程序

`K10 主程序开始` 下按顺序搭建：

1. 设置串口 0 波特率为 115200。
2. 把六个 LED 引脚设为输出，执行 `全部LED关闭`。
3. 清零通信、按键和状态缓存变量。
4. 显示初始页。
5. 设置中文单次语音识别时长为 10000 ms，添加 ID 10—17 的八个命令词。
6. 设置中文语音合成语速为 1。
7. 串口输出 `HELLO|1`。
8. 进入循环，每 20 ms 执行一次：
   - 若 `buttonAFlag=1`，清零标志并输出 `BUTTON_A`。
   - 若 `buttonBFlag=1`，清零标志并输出 `BUTTON_B`。
   - 若串口有可读数据，读取一行到 `rxLine`，执行 `处理电脑指令(rxLine)`。
   - 若 `computerReady=1` 且当前时间与 `lastPingTime` 相差超过 5000 ms，把 `computerReady` 设为 0，熄灭全部 LED，显示“电脑连接已中断”。
   - 依次检查命令 ID 10—17；命中后调用与上表对应的 `发送查询`。

### 7.4 A/B 按键积木

- `当按下A键`中只把 `buttonAFlag` 设为 1。
- `当按下B键`中只把 `buttonBFlag` 设为 1。
- 按键中断里不刷屏、不语音合成、不等待串口；所有耗时操作回到主循环执行。

## 8. 电脑端串口桥

新增独立进程，不把串口循环塞入 FastAPI 请求处理中。启动形式为：

```powershell
community-navigator-bridge --port COM5 --api-base http://127.0.0.1:8000
```

行为约定：

1. 启动时先请求 `/api/v1/health`；成功后打开串口。
2. 收到 `HELLO|1` 后返回 `READY`；版本不匹配时返回明确错误并不接受操作。
3. 收到 `QUERY` 后调用 `POST /api/v1/query`，保存返回的 `session_id`，再把 `device` 状态编码为串口帧。
4. 收到 `BUTTON_A/B` 后调用当前会话的 `events` 接口，再下发最新状态。
5. 尚无当前会话却收到按键时，不调用后端，只返回“请先说出您要办理的事情”。
6. 连接期间每 2 秒发送 `PING`；串口断开后有界重试，不无限快速重连；日志不记录 API Key。
7. Mind+ 上传程序后必须关闭 Mind+ 串口监视并断开设备占用，再启动桥接程序；同一 COM 口不由两个程序同时打开。

## 9. 模型连接与后期本地化

Mind+ 和 K10 不感知实际模型。模型由现有电脑端服务通过环境变量选择：

- `MODEL_PROVIDER=mock`：无密钥测试和课堂保底。
- `MODEL_PROVIDER=openai_compatible`：前期调用云端兼容接口。
- `MODEL_PROVIDER=ollama`、`MODEL_BASE_URL=http://127.0.0.1:11434`、`MODEL_NAME=qwen3:0.6b`：后期本地模型。

切换模型不改串口协议、Mind+ 积木、知识库格式或 K10 显示逻辑。大模型只整理已检索到的社区资料，不得发明时间、地点、材料或联系方式。

## 10. 错误处理

- **未知服务**：电脑端使用固定人工确认话术，下发 `LED|0`，A/B 不推进步骤。
- **模型超时或非法输出**：现有规划层回退到知识库固定步骤；若核心服务也失败，K10 显示需要工作人员处理。
- **电脑端未启动**：桥接程序不打开交互循环，终端显示可操作的启动提示。
- **串口中断**：K10 通过 5 秒心跳超时发现中断，熄灭 LED 并用断线提示替换当前文字，不继续假装操作成功。
- **坏数据**：不展示半帧，不点亮 LED，串口桥记录不含密钥的错误摘要。

## 11. 浏览器扬声器图标

把 `◖))` 文字替换为内联 SVG：左侧是梯形喇叭本体，右侧是两道音波。图标使用现有暖黄色，与“扬声器：…”文字基线对齐，标记为装饰性 `aria-hidden=true`，无需新的图片文件或网络资源。

## 12. 测试与验收

### 12.1 自动化测试

- 短协议的正常编解码、超长、未知命令、非法字段和协议版本测试。
- `DeviceState` 到多行 K10 帧的稳定转换测试，特别验证 `active_leds=[]` 编码为 `LED|0`。
- 使用伪串口和 FastAPI 测试客户端跑通 `HELLO → PING → QUERY → BUTTON_A → BUTTON_B`。
- 服务器不可达、无当前会话按键、未知服务、串口断开的失败路径测试。
- 浏览器 HTML 测试确认旧字符已删除且 SVG 图标存在。
- 原有全部测试仍通过。

### 12.2 实物验收

1. Mind+ 上传完成后断开其串口占用，启动智能体服务和桥接程序，K10 显示“智能体已连接”。
2. 说“你好小行”后再说“书法班”，屏幕、播报和 4 号活动室 LED 一致。
3. 按 A 重复同一步；按 B 逐步前进；末步再按 B 后六灯全灭。
4. “量血压”点亮 3 号卫生站，“社保”点亮 5 号服务大厅，“老人助餐”点亮 6 号便民驿站。
5. “办护照”播报人工确认提示，六灯全灭。
6. 关闭电脑端服务后再查询，K10 显示可理解的错误，不显示技术堆栈。
7. 分别用 Mock 和 Ollama 配置重复上述主流程，Mind+ 积木不做任何修改。

## 13. 交付物形式

- `mindplus/`：积木组图、变量表、逐块搭建手册、命令词表和接线图。
- Mind+ V2 原生项目：在支持 K10 的 Mind+ V2 中实际创建并使用软件的“保存项目”功能导出，不手工伪造未验证的工程格式。当前电脑未检测到 Mind+ 安装，因此原生工程的生成与上传必须在安装 Mind+ V2 后完成。
- `src/community_navigator/device_bridge/`：短协议、状态转换和串口桥。
- `tests/`：短协议、桥接和回归测试。
- `README.md`：先启动智能体、再启动串口桥的小学生可执行操作步骤，以及云端/Ollama 切换方法。

## 14. 实施顺序

1. 先用测试锁定短协议和状态转换。
2. 实现可用伪串口验证的电脑端桥。
3. 修改浏览器扬声器 SVG 图标。
4. 产出 Mind+ 积木组图和逐块搭建手册。
5. 安装并打开 Mind+ V2，按手册创建原生项目并在 K10 上传。
6. 按实物验收清单联调屏幕、扬声器、A/B 键和六路 LED。
