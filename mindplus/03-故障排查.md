# Mind+ K10 联调故障排查

先记住正确顺序：启动电脑端智能体 → 在 Mind+ 上传 → 断开 Mind+ 串口 → 启动 Python 串口桥。

## 1. 提示“COM 端口被占用”

原因通常是 Mind+、串口监视器或另一个桥接程序仍占用同一个 COM 口。

处理：在 Mind+ 断开设备并关闭串口监视器；关闭旧的桥接窗口；再运行 `community-navigator-bridge.exe --port COM号`。不要同时开两个桥接程序。

## 2. K10 一直收不到 `READY`

依次检查：

1. 电脑端 `community-navigator.exe` 是否已经运行。
2. 浏览器能否打开 <http://127.0.0.1:8000/api/v1/health>。
3. 桥接程序使用的 COM 号是否与设备管理器一致。
4. K10 初始化后是否从串口 0 发送了带换行的 `HELLO|1`。
5. Mind+ 是否已经释放 COM 口。

## 3. 中文乱码或指令不能识别

两端必须同时使用串口 0、`115200` 波特率、UTF-8 文本和换行结尾。不要把波特率改成 9600。检查积木中的 `QUERY|`、`BUTTON_A`、`BUTTON_B` 和 `HELLO|1` 是否多了空格或中文标点。

## 4. 点亮了错误地点 LED

先在“点亮地图地点(编号)”中逐个测试 1—6，再按接线表核对 P0、P1、P2、P8、P9、P12。若逻辑正确但地图位置不对，就是纸板地图上的导线插错。程序每次点亮前都应执行“全部LED关闭”，正常时最多亮一个。

## 5. 说话后没有识别

先清楚地说唤醒词“你好小行”，听到唤醒反馈后再说命令。命令词要用 `shu fa ban` 等带空格拼音录入，ID 必须为 10—17。确认中文单次识别时长为 10000 毫秒，并避开嘈杂环境。首版只识别手册中的八个命令，不是任意语音听写。

## 6. K10 重启或屏幕回到初始页

USB 供电不稳、接线短路或上传后复位都可能造成重启。立即断电检查 LED 是否都串有限流电阻、正负极是否反接、是否共地。重新上电后 K10 会再次发送 `HELLO|1`；桥接程序保持运行时会重新返回 `READY`。

## 7. 桥接程序提示电脑端服务不可用

先启动：

```powershell
$env:MODEL_PROVIDER="mock"
.\.venv\Scripts\community-navigator.exe
```

确认健康接口能打开，再启动串口桥。如果使用 Ollama，还要确认 Ollama 正在运行且本机已有 `qwen3:0.6b`。模型失败时智能体会优先使用知识库固定步骤，但核心服务未启动时桥接不能工作。

## 8. 五秒后显示“电脑连接已中断”

桥接程序正常时每 2 秒发送一次 `PING`。K10 连续 5 秒没有心跳就会把 `computerReady` 设为 0、熄灭六灯并显示断线提示。

检查桥接窗口是否关闭、Type-C 数据线是否松动、COM 号是否变化。恢复连接后重启桥接；如果 K10 没有重新发送 `HELLO|1`，按复位键让设备重新初始化。

## 9. A/B 键没反应或连续触发

A/B 事件中只能把对应标志设为 1；主循环再清零并发送一次 `BUTTON_A` 或 `BUTTON_B`。不要在按键事件里显示、播报、读取串口或加入耗时动作。若还没有成功查询，按键会得到“请先说出您要办理的事情”的提示。

## 10. “办护照”仍然亮灯

这是安全故障。确认电脑端未知服务状态发送 `LED|0`，K10 的 `点亮地图地点(0)` 会先调用“全部LED关闭”，并且 `STATE_END` 后才应用。修正前不要用于现场展示。
